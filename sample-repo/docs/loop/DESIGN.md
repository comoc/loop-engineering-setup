# ループ設計書: 仕様と実装の同期(全角数字ID受理バグ修正)

> 無人実行のため人間の承認は得られていない(**未承認・推奨デフォルト採用**)。
> 同期承認必須級の操作(commit / push / 公開API変更 / 依存追加 / Automations 有効化)は行わない。

## 題材候補比較(反復性 / 検証可能性 / 経済価値)

1. **仕様と実装の同期 — 全角数字ID受理バグの修正**(小・仕様根拠明確・実バグ)← **採用(最小)**
2. テスト補完 — 仕様記載の異常系(温度非数値・フィールド数)のテスト追加(小・検証可能)→ backlog へ
3. lint 恒久化 — ruff 設定ファイル導入と CI 化(中)→ 見送り(Automations と同時に検討)

## 設計

- **ゴール(検証可能な完了条件)**: `python3 -m unittest discover -s tests` 全パス **かつ**
  `ruff check src tests` エラー0 **かつ** 全角数字IDを弾くリグレッションテストが存在し
  修正前実装で落ちること(欠陥検出力の実証) **かつ** Checker の High 指摘 0件
- **検証ゲート**: 上記2コマンド。合格基準は各終了コード0
- **Maker**: 調査と修正を実装(.claude/agents/loop-maker.md)。最初にエラー性質判定
  (`InvalidSensorId` / `ValueError` は仕様どおりの想定内異常系=対応不要。仕様との乖離のみ修正対象)
- **Checker**: 判定のみ(.claude/agents/loop-checker.md)。tools は Read, Grep, Glob,
  Bash(検証再実行用)に限定し Write/Edit なし。書込を伴う Bash も定義本文で禁止
- **反復**: Maker 修正 → ゲート実行 → Checker 独立検証 → High があれば差し戻し
- **停止条件**: 反復5回上限 / 2回連続で改善なし(=ゲート不合格数も High 指摘数も減らない
  イテレーションが2回続く。典型例: 同一テストが同一理由で落ち続ける)/ 同一コマンド3回連続の
  環境要因失敗 — いずれかで status を "requires human review" にし要約を STATE.md に残す
- **人間確認の濃淡(可逆性 × 影響範囲)**: 戻せる×狭い(本題材のローカルコード+テスト変更)→
  自動採用し事後サマリ報告 / 戻せない・広い(commit, push, 公開API変更, 依存追加)→
  同期承認必須のため無人実行では行わない
- **状態ファイル**: docs/loop/STATE.md に試行・ゲート結果・未解決・次の一手を記録
  (更新責務はオーケストレータ = /loop 実行主体)
